# FirePath playtest — September 26, 2026

Source: founder's spoken walkthrough on a phone during the hackathon. The consistent issue was too much copy and too much page height. Prioritize a fast, legible judge demo over adding features.

## Changes already pushed

- Public landing: stronger FirePath wordmark, compact globe control, shorter headline, walkthrough below address entry and 211, collapsed resources. Registration now appears immediately after an address result.
- Address result: concise count, explicit "In zone / Outside zone / Unavailable" labels, compact seven-layer list, expandable official source links.
- Walkthrough: simple five-point intro and Begin button; mobile overlay now shows step count, chapter, title, progress and controls, without paragraphs.
- Map: larger viewport, view selector below map, expandable hazard details; shortened flat-map legend and constrained map popups / 3D parcel card on phones.
- Plan / Alerts: removed repetitive "Built from" explanations and per-step reason lines in drills; checklist progress shortened.
- Permits / onboarding: project choice and remaining segmented selectors changed to dropdowns. Existing fee status and current City fee schedule link remain. Prices cannot be inferred for every project from a permit name.
- Profile: recognizable person icon and spaced responder brief lines.
- Print: web print now opens a dedicated document in an iframe instead of printing the whole app page. Needs browser print-preview verification on the deployed app.

## What to check next on the actual phone

1. Confirm Vercel has deployed the latest commit. Sign out. First screen: can a new person state what the app does in five seconds? Does address lookup work?
2. After lookup: does Register my home appear immediately below the result? Is the difference between an outside zone and unavailable data clear?
3. Run the quick tour. Does the small overlay leave the screen and primary controls visible? Is the final page still too long?
4. Open both flat and 3D maps. Tap a location/building. Check that map detail covers no more than about one third of the phone map and that it is easy to close.
5. Choose an ADU under Permits > Projects. Confirm the dropdown visibly selects it and the checklist button follows. The fee remains quote required; do not show a made-up amount.
6. On web, use Print & post > Earthquake plan, inspect print preview. It must show only the generated sheet. The code change passed an Expo web export, but this print interaction has not been manually verified in a browser.

## Still open from the spoken feedback

- Copy across the deeper plan, drill, onboarding and permit screens is still verbose in places. Cut labels and descriptions where doing so preserves safety meaning.
- Drill screen behaves like a plan walkthrough. Add a clear practiced action or scenario step if there is time; do not present it as a live alert.
- Address lookup felt slow. Measure the delay before optimizing; show visible progress while it checks.
- Consider whether the full judging-criteria page belongs in the demo flow, as it is text heavy.
- Founder raised police scanners as an idea. Treat as optional research, not a dependency for the demo.
- Test with the founder's actual phone and desktop. Builds are not equivalent to interaction QA.

## Safety and truthfulness

- A map showing no zone does not prove safety. A missing response must be shown as unavailable.
- Do not claim live City evacuation orders, active responder delivery, verified parcel identity or push alerts when they are prototypes / future integrations.
- Do not fabricate permit prices. The City's current fee schedule is linked; final fees depend on project scope.
